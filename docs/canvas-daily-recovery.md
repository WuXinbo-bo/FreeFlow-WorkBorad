# 画布日常恢复与切换

## 使用入口

- 工作区标题栏的回收站按钮：查看此工作区删除的画布、恢复或逐条永久删除。
- 当前画布或列表画布的操作菜单 → 历史版本：查看时间、来源、大小和节点摘要，再确认恢复。
- 当前画布旁的切换按钮：回到上一个画布；最近画布快捷条直接打开最近四个文件。
- `⌘P`（Mac）/ `Ctrl+P`（Windows）：聚焦画布搜索，搜索当前工作区和最近文件，方向键选择、回车打开、Escape 清空。
- `⌘⇧O`（Mac）/ `Ctrl+Shift+O`（Windows）：返回上一个画布。原有思维节点快捷键保持可用。

## 数据与恢复规则

每个画布文件所在目录的 `.freeflow-recovery` 保存本地恢复记录。它不进入工作区画布列表，也不上传到 GitHub；另一设备使用 GitHub 的远程历史，本地恢复记录只在本地存在。

保存覆盖、远程拉取和历史恢复前保留原版本。每个文件保留最近 30 个版本，累计上限 200 MB（单个超过上限的当前安全副本仍保留）。内容没有变化的副本不重复写入。自动保存也遵循此规则；重命名携带历史记录。恢复画布内容时维持当前同步 ID，恢复前的内容仍可再次恢复。

删除会先写入完整副本和 SHA-256 校验信息，再移除原文件。回收站不自动过期，需要时逐条永久删除；永久删除需要二次确认。当前打开的画布应先切换到另一画布再删除。工作区外的最近文件，其回收站位于该文件自己的目录。

恢复到原目录遇到同名文件会自动改名；该副本获得独立同步 ID，避免与现有画布共享身份。损坏文件仍可从回收站原样取回再使用现有修复入口。历史恢复会先验证历史文件结构及校验和；校验失败时保留当前画布。

恢复记录包含画布数据和内嵌图片，外部附件继续引用原位置，不复制任意外部文件。GitHub 拉取会合并校验后的附件，保留其他画布及历史版本使用的旧附件。外部文件被用户自行移动或删除后，不承诺附件可恢复。

## 同步状态

“已保存到本机”和远程状态分别显示。首次检查前显示“尚未检查”，账本只能表示“上次已同步”。检查后显示待上传、待拉取、冲突和远程删除数量，并注明检查时间；编辑、保存、外部目录变化和重新聚焦会让检查结果失效，标记为“上次检查 / 需要检查”。冲突可直接进入 GitHub 设置处理，失败可重试检查。

上传、拉取和恢复期间保留现有的自动保存互斥与编辑保护。下载完成后会重新核对本地内容；期间已发生变化则停止覆盖。实际网络同步仍遵循 GitHub API 的轮询与请求约束，本次不新增后台实时协作服务。

## 状态机与回归路径

1. 恢复窗口：关闭 → 读取列表 → 列表 → 预览/确认 → 恢复中 → 成功关闭，或失败留在窗口。取消、Escape 和失败均保留画布；异步读取期间按钮禁用，旧响应失效，窗口关闭恢复焦点。
2. 文件切换：空闲 → 检查未保存内容 → 保存/放弃/取消 → 读取 → 成功切换或失败保留原内容。延迟读取时的新编辑仍受原有版本检查保护；快速重复操作由互斥状态拒绝。
3. 同步：未检查/过期 → 检查或同步中 → 检查结果与时间，或错误/重试。后续本地变化立即使结果过期；换工作区、换仓库清除旧计划。
4. 磁盘替换：验证远端 → 暂存与完整性校验 → 文件锁 → 核对本地仍未变化 → 历史副本 → 附件落盘 → 原子替换画布 → 更新账本 → 清理暂存。任意失败停止后续步骤；已写入的内容寻址附件可以安全保留。

验证命令：`node scripts/check-canvas-recovery.js`、`node scripts/check-workspace-daily-use.js`、`node scripts/check-board-workspace-desktop.js`、`node scripts/check-github-sync-multidevice.js`，以及 `npm test`。桌面测试使用独立数据目录；GitHub 多设备测试使用模拟 Git 对象服务器，不操作用户仓库。
