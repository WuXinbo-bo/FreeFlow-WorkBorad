# AI 镜像原生浮层与恢复链

本文记录 AI 镜像使用 `WebContentsView` 时，应用菜单、系统设置与镜像页面的层级处理，以及本轮验证范围。它不改变 AI 助手插件的安装协议，也不将第三方 AI 网页内容接入应用权限接口。

## 目标与边界

第三方镜像与应用主界面属于不同的原生视图。提高主界面 DOM 的 `z-index`，无法让 DOM 菜单覆盖镜像的原生视图。过去通过临时停止镜像避让设置，会使网页实例、未发送内容和滚动位置丢失。

本轮将少量明确的应用界面放入独立原生浮层，显示在镜像上方。镜像页面继续保留，浮层外露出的镜像区域仍可交互。复杂的画布对话框继续使用 DOM；确实覆盖镜像时，暂时隐藏并移除镜像视图的挂载，保留网页实例，关闭后恢复。

这里的“隐藏”与“停止”不同：隐藏保留 `webContents`，停止销毁镜像实例。隐藏期间会启用后台节流，不能据此承诺第三方网页的定时器、音视频或流式连接始终以相同速率运行。

## 实现分层

| 层 | 文件 | 职责 |
| --- | --- | --- |
| 镜像原生视图 | `electron/web/webContentsViewEmbed.js` | 创建与复用镜像、挂载与移除、显隐、会话身份、尺寸与焦点 |
| 应用原生浮层 | `electron/web/mirrorOverlay.js` | 延迟创建浮层视图、加载就绪握手、层级、尺寸、来源校验、崩溃清理 |
| 浮层窄桥接 | `electron/web/mirrorOverlayPreload.js` | 仅暴露 `onPresent`、`request`、`emit`、`ready` |
| 主进程协调 | `electron/main.js`、`electron/preload.js` | 浮层请求转发、焦点归属、穿透与导航清理、原生视图重排 |
| 主界面代理 | `public/src/runtime/mirrorOverlay/mirrorOverlayHost.js` | 将既有菜单动作和设置回调转为受限 RPC，管理 DOM/原生界面归属 |
| 可见性协调 | `public/src/runtime/mirrorOverlay/mirrorVisibilityController.js` | 合并显隐请求，仅确认成功且会话匹配的结果，避免旧异步恢复已停止镜像 |
| 浮层页面 | `public/mirror-overlay.html`、`public/src/runtime/mirrorOverlay/overlayEntry.js`、`overlay.css` | 挂载真实设置组件、结构化菜单、键盘交互与主题 |
| 工作台集成 | `public/src/runtime/workbenchRuntime.js` | 选择原生或 DOM 路径、识别遮挡、同步布局与恢复镜像 |

浮层复用现有 `mountSettingsCenter`，不另写一套设置保存逻辑。原生菜单使用动作 ID 与文字、图标等结构化数据，由主界面执行既有动作；不传递任意 HTML 或脚本。

浮层只加载当前本机应用的 `/mirror-overlay.html`，启用沙箱、上下文隔离并关闭 Node 集成。主进程校验发送者及主 frame 的精确页面地址，限制浮层 ID、事件和接口；拦截导航与弹窗。外部链接回到既有安全 URL 打开路径。

## 原生覆盖范围

| 界面 | surface ID | 行为 |
| --- | --- | --- |
| 系统设置 | `settings` | 半屏设置浮层；复用设置内容、保存、快捷键录制及插件管理 |
| 右侧面板更多菜单 | `shell-more` | 原生菜单覆盖镜像，动作仍回到主界面执行 |
| 应用更多菜单 | `desktop-more` | 同上 |
| AI 镜像控制菜单 | `mirror-controls` | 映射当前镜像控制动作，过期动作不得重新启动已停止镜像 |

没有活动原生镜像时，菜单保留原有 DOM 路径。设置首次移交给原生浮层前，检查原 DOM 设置是否存在未保存草稿；已有草稿时保留原组件，避免切换成另一份编辑状态。成功移交后，设置由同一个原生组件继续承载，即使镜像随后停止，也不在两份设置实例间来回切换。

## 状态机与恢复规则

镜像实例与应用浮层分别管理生命周期，不能用一个“是否打开”变量代替。

| 场景 | 进入或连续操作 | 退出与恢复 |
| --- | --- | --- |
| 打开原生菜单/设置 | 浮层延迟创建；页面加载和 `ready` 均完成后挂载到镜像上方 | 关闭浮层只隐藏并移除挂载；保留浮层组件和镜像实例 |
| 原生浮层已打开时更新 | 相同展示内容去重；尺寸与主题更新不重复抢焦点 | 同一设置组件保留草稿与当前页；只有新的 `sectionRevision` 才切换设置栏目 |
| 点击菜单外部/切换菜单 | 菜单失焦后再次确认当前版本和焦点，避免短暂失焦误关闭 | 只关闭当前菜单；原生设置不会因用户点击外露镜像区域而自动关闭 |
| 设置保存中关闭 | 调用真实组件的关闭流程；保存中可返回拒绝关闭 | 保留设置，待保存结束后再允许正常退出；不绕过保存保护 |
| 复杂 DOM 对话框遮挡镜像 | 隐藏镜像并从父原生视图移除，保留网页实例 | 遮挡消失且会话仍有效时，使用当前尺寸重新挂载；恢复前台调度 |
| 开启完全穿透 | 关闭当前原生浮层展示，镜像进入隐藏路径 | 退出穿透后，仅恢复仍有效的镜像会话；不会新建镜像来“补恢复” |
| 快速反复开关或切换 | 主界面展示代次、原生展示修订和镜像会话身份共同过滤旧结果 | 以最后一次有效目标为准，旧加载、旧显隐、旧菜单事件不覆盖新状态 |
| 显隐 IPC 失败 | 失败结果不记为成功确认 | 后续同步仍可重试；不会因为错误确认而永久停在隐藏状态 |
| 显式停止镜像 | 使会话/挂载代次失效，清除并销毁镜像实例 | 关闭设置或旧异步完成不得重建镜像；只有用户重新启动才创建新实例 |
| 主页面 reload/导航/窗口关闭 | 清除浮层和镜像原生实例，拒绝待处理浮层请求，清空焦点归属 | 新主页面重新初始化；不承诺保留跨 reload 的未保存设置或网页草稿 |
| 浮层加载失败或 renderer 崩溃 | 销毁不可用浮层，撤回 DOM 隐藏标记，恢复 DOM 路径 | 原生设置本次页面生命周期内停止接管，避免重复失败与多份草稿漂移；提示检查未保存设置 |

镜像显隐请求带 `targetId`、`syncSessionId` 等身份。停止、切换目标、导航后，旧请求即使稍后完成，也不能恢复旧实例或改变新会话。加载期间发生隐藏、停止，同样需要在加载结束后重新检查当前状态。

原生浮层关闭时保留的是当前 renderer 中的组件状态；renderer 崩溃会丢失其未保存内存草稿。回退 DOM 面板时，有脏草稿或正在保存的原组件不重新加载；其余情况重新读取已保存设置。该路径以保留可确认的已保存内容、明确提示为边界，不伪装成崩溃草稿恢复。

## 设置 RPC 与文件写入保护

设置中的桌面、GitHub 同步和 AI 运行时操作采用明确的方法白名单。GitHub 异常转发保留 `code`、`operationId`、冲突、附件、`localChanged` 等结构化信息，以继续查询未完成操作并显示已写入文件或恢复产物。

涉及画布文件的操作沿用现有 `runGitHubBoardFileOperation` 保护，通过开始/结束租约覆盖整个操作区间。浮层崩溃不代表后台 IPC 已经停止：主界面仍跟踪正在进行的 GitHub 写入及操作日志确认，在它们结束后才释放租约，避免自动保存与尚未结束的拉取竞争。

浮层内的正常失败路径通过 `finally` 结束租约；崩溃路径由宿主接管释放。操作通知及远端更新转发到浮层，浮层转回主界面的事件限制为既有允许类型，并防止接收事件再次回传形成循环。

## 复杂对话框的降级边界

本轮未把文件预览、导出预览、图片管理、教程等所有画布界面改成原生页面。它们仍使用现有 DOM 组件。遮挡判定结合应用浮层的可见位置与镜像区域，以及左右工作区重叠关系；需要避让时采用保留实例的隐藏/移除挂载路径。

后续新增 portal、独立挂载到 `document.body` 的弹层或跨分区浮动工具栏时，必须确认它被现有遮挡检测覆盖，不能仅依赖 CSS 层级。应同时验证打开、连续操作、关闭恢复和快速反复操作；没有覆盖到的 DOM 弹层仍可能被原生镜像盖住。

Windows 原生外部窗口嵌入保留既有平台路径。本文的原生菜单与设置覆盖验证针对 `WebContentsView` 镜像，不代表已经验证 Win32 外部窗口层级行为。

## 可重复验证

在项目根目录使用 Node 运行；Chromium 与桌面脚本需要项目安装的 Playwright/Electron 依赖。

统一入口为 `node scripts/run-mirror-overlay-tests.js`，按顺序执行这些检查，真实桌面测试最后执行，避免多个原生窗口互相抢焦点。仅运行逻辑与 Chromium 检查时使用 `node scripts/run-mirror-overlay-tests.js --no-desktop`；任一检查失败后停止，不把后续未执行项计作通过。

| 脚本 | 验证层级与重点 |
| --- | --- |
| `node scripts/check-webcontents-view-embed.js` | 模拟 Electron：并发加载复用、旧会话、加载中隐藏/停止、失败重试、反复显隐、父窗口替换、外部销毁与清理 |
| `node scripts/check-ai-mirror-target-lifecycle.js` | 模拟 Electron/Win32：目标窗口待加载时的归属、取消与复用，旧加载/切换/停止/dispose 恢复，Win32 清理与显隐的会话匹配 |
| `node scripts/check-mirror-runtime-lifecycle.js` | 直接执行生产生命周期函数：待启动时停止、旧完成/失败与新会话竞争、WebContentsView/Win32 模式切换、失败重试、重复停止及视频轨道释放，共 11 项 |
| `node scripts/check-mirror-overlay-manager.js` | 模拟 Electron：延迟创建、加载/ready 顺序、最新展示、原生层级、焦点安全更新、IPC 来源与白名单、崩溃及清理 |
| `node scripts/check-mirror-visibility.js` | 纯逻辑：显隐合并、成功确认、失败重试、会话切换、停止后的旧完成 |
| `node scripts/check-mirror-overlay-host.js` | Chromium + 模拟原生桥：DOM/原生归属、展示去重、栏目/主题、失败回退、旧菜单、崩溃后文件锁持续到后台操作确认 |
| `node scripts/check-mirror-overlay-ui.js` | Chromium + 真实设置组件：15 组布局、草稿关闭重开、保存阻止关闭、快捷键、异常元数据、租约 finally、菜单键盘/焦点、事件与外链 |

Chromium UI 测试使用临时本机服务及模拟数据，不需要用户 GitHub 账号或 AI 凭据。真实 Electron 测试使用临时数据目录与本地流式镜像网页，不修改用户已有画布，也不把真实第三方 AI 服务可用性纳入断言。

## 本轮已确认与待验证

截至本文编写时，上述七项逻辑/Chromium 验证已通过。其中 Win32 相关逻辑使用模拟依赖执行，不等同于 Windows 原生窗口实测。macOS 真实 Electron 已通过以下场景：

- 原生菜单及半屏设置覆盖镜像，原生截图与视图层级检查。
- 镜像未发送草稿、滚动位置、同一 `webContents` 身份保留；本地流式更新继续。
- 设置打开时，在未覆盖的镜像区域继续输入。
- 在真实浮层录制并保存快捷键，通过已注册的全局快捷键回调验证穿透开关及恢复；这不替代操作系统物理按键分发测试。
- 连续 5 轮设置打开/关闭，不重复加载镜像。
- 设置浮层跟随窗口缩放与全屏切换；尺寸不越界，镜像仍为同一实例。
- 复杂 DOM 弹层出现后镜像暂时移除挂载，关闭后恢复原实例；原生菜单在焦点转向镜像后关闭。
- 显式停止后，旧菜单动作不能重新启动镜像；用户重新启动产生新实例。
- 主页面 reload 清理镜像与浮层实例。
- 人为使设置浮层 renderer 崩溃后回到 DOM 设置；关闭后镜像恢复，支持继续输入中日文 Unicode 文本。
- 人为使主界面 renderer 崩溃后，清理原生子视图并自动重新加载画布。

多轮回归中还修复了关闭与布局同步并发导致浮层自行重开的竞态：关闭通知先同步更新界面状态，原生移除挂载可异步完成。受控测试同时验证等待关闭期间连续同步不会重开，以及主动重开后旧关闭结果不会误关新界面。

原有桌面导航回归中，对文件预览尺寸提交及全屏状态增加等待实际状态完成的断言，避免把异步提交期间的瞬时值当作最终结果；未调整这些功能的产品行为。Unicode 输入验证不等同于系统输入法候选窗口的人工测试。

Windows 尚未运行本轮原生桌面测试，原生层级、焦点、穿透及 Win32 外部窗口行为仍需在 Windows 上验证。macOS 本地镜像测试通过，也不代表所有第三方网页的登录、弹窗、流式网络、输入法和多显示器组合已经逐一验证。
