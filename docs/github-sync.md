# GitHub 多设备画布同步

[返回首页](../README.md) · [开始使用](getting-started.md)

FreeFlow 将画布结构和符合规则的附件写入**用户自行授权的私有 GitHub 仓库**。开发者的 FreeFlow 源码仓库与官方插件下载源不承担用户画布存储。

同步用于个人在不同设备之间接续工作，需要联网检查、上传或拉取。它不提供多人实时共同编辑，也不将“保存到本机”当成“已经上传”。

## 第一台设备

1. 保存当前画布，打开所需本地工作区。
2. 进入“系统设置 → GitHub 同步 → 连接与规则”，选择一种授权方式。
3. 选择或创建自己控制的私有同步仓库，确认远程分支。
4. 回到“工作区同步”，先检查当前文件夹的差异，再上传选定内容。
5. 确认结果显示成功，检查附件提示。首次使用建议先用不重要的示例画布验证。

同步配置包含目标仓库与分支；本地工作区决定扫描和拉取位置。切换工作区或仓库后需要重新检查，不要假设新位置沿用旧检查结果。

## 两种授权方式只选一种

| 方式 | 需要什么 | 适用情况 |
| --- | --- | --- |
| 个人访问令牌（PAT） | 用户自己生成、能访问指定仓库的令牌 | 希望直接连接自己控制的仓库 |
| 设备授权（Device Flow） | 已启用 Device Flow 的 GitHub App／OAuth App 的公开 Client ID，及浏览器内确认授权 | 应用维护者已配置授权应用，用户通过浏览器登录 |

**PAT 连接不需要填写 Client ID 或授权应用类型。** Client ID 是公开的应用标识，不是密码，也不能替代仓库访问权限；Device Flow 完成后由 GitHub 签发实际访问凭据。桌面端不应保存 Client Secret。

使用 fine-grained PAT 时，只选择自己的同步仓库，并按实际操作授予仓库内容读写权限。创建新仓库所需权限与访问已有仓库不同；最简单的最小权限方式是先在 GitHub 创建私有仓库，再授权该仓库。Classic PAT 的私有仓库范围通常更宽，应评估权限后使用。

权限、组织策略、令牌有效期都可能影响连接。`401` 通常表示凭据失效；`403` 可能是仓库权限、组织批准或接口限制，应查看应用提供的具体错误。

令牌只在应用内输入。不要发到聊天、Issue、截图、命令参数、Git remote URL 或源码中。泄露后先在 GitHub 撤销，再创建替代凭据。

## 另一台设备拉取

1. 安装兼容版本的 FreeFlow，创建或打开希望接收画布的本地工作区。
2. 使用有相应权限的凭据连接**同一个仓库和同一个远程分支**。
3. 在“远程画布”查看内容，选择拉取。默认保存到当前工作区，可按需另选位置。
4. 拉取成功后刷新工作区列表，打开画布继续工作。
5. 后续工作前先检查远程更新，完成编辑后保存，再检查与同步。

不同设备的本地文件夹名称不必完全相同。附件是否可用取决于它是否已同步、是否需要原本机路径及是否符合规则。仅出现在本地的外部文件，另一设备可能需要重新关联。

## 理解状态

| 状态 | 含义与建议 |
| --- | --- |
| 已保存到本机 | 本地文件已写入；不代表远端已更新 |
| 待上传 | 本机有远端尚未拥有的修改 |
| 待拉取／远端有更新 | 远端有不同内容，先检查后拉取 |
| 双方有修改／冲突 | 保留双方内容，按界面选择合并或保留版本 |
| 上次同步成功 | 记录上次结果；有新编辑后仍应重新检查 |
| 结果待确认／中断 | 网络或退出使操作结果尚未核对；恢复连接并检查，避免重复上传 |
| 部分附件未同步 | 画布结构可以同步，但相关附件只能以占位信息呈现 |

应用会在合适时机轻量检查远端，隐藏窗口暂停、失败后退避。发现远端变化不会在后台直接覆盖正在编辑的画布。关闭应用期间另一设备的变化，也需要重新检查。

## 附件默认规则

以下是项目默认策略，MiB = 1,048,576 字节，并非 GitHub 官方容量承诺：

| 项目 | 默认策略 |
| --- | --- |
| 图片 | 单个最多 5 MiB |
| 普通文件／文档 | 单个最多 10 MiB |
| 视频 | 不同步内容，保留占位信息 |
| 批次附件 | 25 MiB 预算 |
| 仓库资源 | 200 MiB 提醒，500 MiB 上限 |

超过限制、禁用类型或无法读取的附件不会伪装成已完整同步。本机原文件不被删除，远端保留名称、大小及原因等占位信息。仓库历史仍可能累计体积，删除当前文件不等于清除 Git 历史；不应将同步仓库当作视频或大文件网盘。

## 冲突、删除与恢复

- 两台设备同时修改同一内容可能产生冲突；没有共同基线且内容不同时，不自动覆盖。
- 文件重名、重复画布身份、路径不兼容及缺失附件会停止不安全的写入，并提示处理。
- 本机找不到文件不等于确认远端删除；普通批量同步不会直接把这种缺失传播为删除。
- 远程拉取和覆盖前使用已有历史恢复保护；本地 `.freeflow-recovery` 记录保留在本机，不作为历史目录上传。
- 远程 Git 历史、本机恢复记录与独立备份用途不同。重要工作应保留自己的完整备份。

遇到待确认状态时先恢复网络并检查，不要连续点击上传或通过删除配置文件“解锁”。如果需要人工求助，提供错误代码及脱敏操作步骤，保留当前画布与恢复记录。

## 三套 GitHub 用途彼此独立

| 用途 | 位置 | 凭据关系 |
| --- | --- | --- |
| FreeFlow 源码与应用发布 | 开发者的项目仓库 | 普通下载无需用户同步 Token |
| 官方插件目录与安装包 | 开发者项目的 `plugins` 分支与 Release 附件 | 公开分发，不使用用户同步 Token |
| 用户画布同步 | 用户自己的私有仓库 | 只使用用户明确授权的访问凭据 |
